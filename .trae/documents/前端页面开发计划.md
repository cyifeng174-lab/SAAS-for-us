# 水果批发商进销存小程序 - 前端页面开发计划

## 一、项目背景与目标

### 1.1 项目背景
- **项目名称**：SAAS for us - 水果批发商进销存小程序
- **目标用户**：水果产地中间商
- **使用场景**：嘈杂、忙碌的水果批发市场和加工厂
- **技术栈**：
  - 前端：uni-app (Vue 3, 组合式 API `<script setup>`)
  - UI框架：uni-ui 或原生手写
  - 后端：uniCloud (阿里云版)
  - 数据库：uniCloud DB (MongoDB)

### 1.2 UI设计原则
- **大按钮**：方便快速点击，减少误操作
- **大字体**：在嘈杂环境中清晰可见
- **极简操作**：减少操作步骤，提高效率
- **少弹窗**：避免打断用户操作流程

### 1.3 开发目标
构建一个完整的 MVP（最小可行性产品）闭环，实现从采购、加工、库存到销售的完整业务流程。

## 二、后端系统现状分析

### 2.1 已完成的云函数
1. **sales_order_create** - 销售开单云函数
   - 支持批发/零售两种模式
   - FIFO（先进先出）扣减批次库存
   - 计算真实成本和毛利
   - 自动生成财务流水
   - 使用事务保证数据一致性

2. **process_and_stock_in** - 加工入库与成本分摊云函数
   - 将原果加工成成品
   - 按重量比例分摊成本
   - 更新库存记录（支持移动加权平均成本）
   - 生成加工单记录

### 2.2 已完成的数据库表
- `customers` - 客户表
- `suppliers` - 供应商表
- `inventories` - 库存表
- `purchases` - 采购单表
- `processing_orders` - 加工单表
- `sales_orders` - 销售订单表
- `financial_ledgers` - 财务流水表

#### Tab 1: 首页/工作台 (`pages/index/index.vue`)

#### Tab 2: 销售开单 (`pages/sales/billing.vue`)

  - 一键提交扣库存
- **交互设计**：
  - 大数字键盘
  - 快速选择常用客户
  - 实时计算总价和毛利

#### Tab 3: 库存总览 (`pages/inventory/list.vue`)
- **功能定位**：仓库大管家
- **核心展示**：

  - 点击商品进入详情

- **功能定位**：个人中心与基础设置

  - 当前账号信息
  - 基础数据维护（商品规格库管理）
  - 基础设置
  - 日结数据导出 Excel

### 3.2 二级核心业务页面

#### 采购与加工线
1. **采购单录入** (`pages/purchase/create.vue`)
   - 对应 `purchases` 表
   - 记录原果名称、重量、单价、付款状态

2. **加工与成本分摊** (`pages/processing/create.vue`)
   - 对应 `process_and_stock_in` 云函数
   - 录入人工/包装/运费

   - 一键计算成本并入库

#### 财务与查账线
3. **客户与账本** (`pages/customer/list.vue`)
   - 对应 `customers` 表
   - 展示所有客户列表
   - 显示当前总欠款余额

4. **收款与核销** (`pages/finance/receive.vue`)
   - 对应 `financial_ledgers` 表
   - 选择客户，输入收款金额
   - 自动按先进先出抵扣历史欠款

5. **销售历史单据** (`pages/sales/history.vue`)
   - 对应 `sales_orders` 表
   - 按天展示销售单
   - 支持查错、作废或退货

## 五、技术实现要点

### 5.1 金额处理规范
- **存储单位**：统一使用"分"（整型 int）
- **显示单位**：转换为"元"显示
- **转换函数**：
  ```javascript
  // 分转元
  const fenToYuan = (fen) => (fen / 100).toFixed(2)
  
  // 元转分
  const yuanToFen = (yuan) => Math.round(yuan * 100)
  ```

### 5.2 数据库事务
- 所有涉及库存扣减和财务记账的操作，必须使用数据库事务
- 云函数中已实现事务处理，前端只需调用

### 5.3 多租户预留
- 所有数据库表已预埋 `tenant_id` 字段
- 当前版本默认值为 'default'
- 未来扩展时只需从 token 中获取 tenant_id

### 5.4 代码规范
- 使用 Vue 3 组合式 API `<script setup>`
- 详细的中文注释
- 组件化开发，提高复用性

### 5.5 UI组件库
- 优先使用 uni-ui 组件
- 必要时手写组件，保持轻量

## 六、开发顺序建议

### 推荐的开发路线（敏捷开发）

```
第一步：销售开单页面
   ↓
第二步：加工与分摊页面
   ↓
第三步：库存总览页面
   ↓
第四步：用销售开单卖掉库存，完成闭环
   ↓
第五步：首页/工作台
   ↓
第六步：采购单录入
   ↓
第七步：客户与账本
   ↓
第八步：收款与核销
   ↓
第九步：销售历史单据
   ↓
第十步：我的/设置
```

### 为什么这样安排？

1. **销售开单优先**：这是最高频的操作，先完成可以快速体验核心功能
2. **加工入库其次**：产生真实成本的库存，为销售开单提供数据
3. **库存总览第三**：验证加工入库的结果，查看库存状态
4. **完成闭环**：用前三步完成一个完整的业务流程，验证系统正确性
5. **后续完善**：逐步添加其他功能，丰富系统

## 七、风险与注意事项

### 7.1 技术风险
- **并发问题**：云函数已使用事务处理，前端无需担心
- **精度问题**：金额统一使用"分"，避免浮点数精度问题
- **网络问题**：需要处理网络异常，提供友好的错误提示

### 7.2 业务风险
- **库存超卖**：云函数已做校验，库存不足时会拦截
- **客户欠款超额**：需要在开单时提醒，但不强制限制
- **数据一致性**：云函数使用事务，保证数据一致性

### 7.3 用户体验风险
- **操作复杂**：遵循"大按钮、大字体、极简操作"原则
- **加载慢**：优化查询，使用分页加载
- **错误提示不清晰**：提供友好的中文错误提示
